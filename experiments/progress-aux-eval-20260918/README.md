# 首 Boss + 失败进度辅助候选云端评估

旧 438 参数候选来自事先闭合的受控分支数据。主标签仍是是否击败目标 Boss；只有两臂都失败且实际到达幕/层数不同时，才以 `0.25` 权重加入进度排序。五折离线门禁通过：主目标选择值 `0.07447 → 0.08511`，主 NLL `0.97130 → 0.69141`，失败进度辅助 NLL `0.90437 → 0.84739`。

候选已迁移到 Linux 471 参数运行模型：109 个旧参数变化，33 个新功能参数原值不变。独立真实策略读回覆盖 254 个 gate、1016 个冻结动作，分数增量最大误差 `2.8866e-15`，119 个 gate 的最高分集合发生变化；没有读取自然评估结果，也没有部署候选。

自然评估沿用原先在任何自然结果产生前声明的 60 对、120 局全新种子分配。CLab 只有 4 GiB 内存，因此在启动前把执行并发改为单工作进程；种子、顺序、模型、样本量和门禁均不变。候选必须获得更多目标成功，且精确单侧配对检验 `p <= 0.05` 才算通过。无效局保留在完整分母中视为失败，不延长样本，不用评估结果重拟合，不自动部署。

`sts2-progress-aux-handoff.service` 等当前持续采样批次干净闭合后自动切换到评估。它不会杀死活跃游戏；评估完成或失败后恢复 `sts2-cloud-goal.service`。已启动的评估在重启或故障后保留并不重跑。
